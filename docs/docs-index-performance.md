数据来自 `origin/production` 的本地内容副本：42,689 份 Markdown/MDX 文档，4 个入学年份、562 个专业目录。专业映射使用相邻 `hoa-major-data/major_mapping.json`，没有使用主工作区的 mock 内容或样例专业映射。

基线为本次任务开始时的工作区（HEAD `80ef65e7`，含当时已有的未提交修改）；优化版加上本次元数据索引和年级目录范围调整。以下是 Windows 本机测量，不是 VPS 或 Cloudflare Worker 的延迟。

## 请求时的元数据工作

每个版本在独立 Node 进程中加载模块，按 SEO、2023 年级目录、2023/01041 专业目录、该专业课程列表的顺序调用。记录函数执行时间及调用期间的 `readFileSync` / `readdirSync` 次数；每个函数立即重复一次。模块导入本身不计入函数计时。单次样本，不代表分位数。

| 首次调用            |    优化前 |  优化后 | 读取文件次数：前 → 后 |
| ------------------- | --------: | ------: | --------------------: |
| SEO                 | 58,862 ms | 4.45 ms |            38,398 → 1 |
| 2023 年级目录       | 79,352 ms | 4.68 ms |            24,512 → 1 |
| 2023/01041 专业目录 |    308 ms | 5.59 ms |               139 → 2 |
| 专业课程列表        |    185 ms | 3.33 ms |               126 → 1 |

优化后的这些调用均没有 `readdirSync`；专业目录的两次读取分别是专业清单和当前专业的目录分片。四个函数的重复调用均无文件读取，测得耗时均小于 0.2 ms。SEO 原来读取约 122.9 MB 正文，优化后只读取 40,224 字节索引。

2023 年级目录的 JSON 字符数从 4,093,953 降到 58,219。年级页仅携带专业入口；进入专业后仍使用完整专业目录。2023/01041 专业目录和课程列表的序列化字符数分别保持 23,023 和 27,401。

## 构建与部署约束

`pnpm build` 先运行 `scripts/generate-docs-index.mjs`，再运行 Next.js 构建。生成器复用现有 SEO、目录和课程字段处理规则；SEO 的最新年份优先、同年 URL 排序、大小写归一化、占位课程 noindex 规则保持一致。路径索引保存相对路径，不绑定构建机的绝对目录。

正式数据的索引生成耗时 228.48 秒，总体积 32,804,573 字节。这是一次性的构建成本，运行时按需读取和缓存分片，不在每个进程首次请求时读取全部索引。Next.js standalone 文件追踪显式包含生成的 JSON。内容与索引应一起重新构建；生产环境缺少索引或版本不兼容时会报错，不回退到同步扫描全站。开发模式始终读取实时内容。

前后两个基准 standalone 包均构建成功；优化包内的 1,132 个索引文件逐个检查了 JSON 格式、版本和数据字段。构建中的未压缩全年目录仅用于生成及兼容完整树的读取入口，年级、专业和课程请求使用对应的分片。

基准环境为 Node 24.20.0、Next.js 16.4.0、Windows。Fumadocs 生成器同时打开大量文件时遇到读取失败，基准构建使用只作用于测试进程的并发限制（64）。Turbopack 测试未完成后，前后两个副本统一使用 Webpack，并在副本中把集合导入改为生成文件的显式路径、禁用未使用的可选 Satteri 编译器。正式规模的构建类型检查曾耗尽本机可提交内存，基准副本跳过了这一步重复检查；这些基准设置没有写入主工作区配置。

主工作区已执行 `make check` 的等效命令：lint、格式检查、Next 路由类型生成、Fumadocs 生成、TypeScript、knip；另有 74 项测试通过。这不等于正式规模的标准构建类型检查通过。

本次没有修改 VPS、重启线上容器或清理线上缓存，也没有修改 Worker。源站优化不能单独证明 Worker 的 `Promise did not resolve to Response` 错误已解决。
