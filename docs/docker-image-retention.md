# VPS Docker 镜像保留策略

部署默认仅输出清理预览，不执行删除。默认值是 **14 天、最近 5 个唯一镜像 ID**：只有同时超过 14 天、且不在最近 5 份内的镜像才会成为候选。时间使用镜像的 `Created`（构建时间），不是拉取时间。相同 ID 的多个标签只算一份；共享 Docker 层由 Docker 自身管理，候选镜像大小之和不等于可释放磁盘量。

## 保护范围

- 所有运行中和已停止容器引用的镜像，包括其他容器对同一 ID 的引用。
- 本次部署前的镜像，即使它很老或不在最近 5 份内，也保护至本次清理结束。
- 最近 5 个唯一项目镜像、未满或刚满 14 天的镜像，以及本地 `latest` 标签指向的镜像。
- 存在其他仓库标签或 digest 引用的共享镜像全部跳过。

只识别 `ghcr.io/hoahrb/hoa-fuma` 的精确仓库引用；无标签镜像必须携带精确来源标签 `org.opencontainers.image.source=https://github.com/HOAHRB/hoa-fuma`。无法确认归属的旧无标签镜像保留，不使用全局 prune。标签来源可从 CI 的 docker/metadata-action 确认；历史镜像是否包含此标签仍需在 VPS 上预览核实。

## 部署与回滚

CI 按本次 build-push-action 返回的 digest 拉取、启动镜像。新增本地 `deploy-<run_id>-<attempt>` 标签，并为替换前的镜像增加 `rollback-<run_id>-<attempt>` 标签，避免仅使用 `latest` 时旧镜像难以识别。标签不会复制镜像层；重复构建若得到相同 ID 不会增加保留份数。CI 串行运行，避免本仓库工作流之间部署和清理重叠。

VPS 需要 `python3`、`base64` 和 Docker；脚本在替换容器前检查 Python。新容器通过容器内 HTTP 检查后才生成预览或清理。检查失败不会清理，也不会自动回滚；可以按日志中的旧 ID 或 rollback 标签重新创建容器，并复用现有部署的端口、网络和环境变量。

## 审阅后启用

1. 部署此改动后，从 Actions 的部署日志查看 `PREVIEW` 及每个镜像的 `KEEP` / `DELETE`、完整 ID、构建时间、引用和保护理由。此阶段不会删除 VPS 镜像。
2. 确认候选归属、保留时间和份数后，再将仓库 Actions 变量 `FUMA_IMAGE_CLEANUP_APPLY` 设为字符串 `true`。**必须先获得实际删除授权**。此变量为持续启用开关，后续每次成功部署都会重新计算并清理；不是锁定某次预览的候选集合。
3. 删除或清空该变量即可恢复预览模式。时间和份数在工作流的脚本调用中显式配置，默认 `--days 14 --keep 5`；两处调用需同步修改。

也可在 VPS 上使用已审阅的脚本手动预览：

```sh
python3 cleanup-images.py --days 14 --keep 5
```

取得删除授权后才追加 `--apply`。每次执行都会重新获取清单。删除前再次检查标签和容器引用；Docker 命令不使用强制选项。检查或删除发生错误会中止，并保留错误日志；已完成的删除不能撤销。外部手动部署仍应与清理错开，工作流锁仅覆盖本 CI 工作流。

## 验证

```sh
python3 -m unittest discover -s scripts -p 'test_cleanup_images.py' -v
```

测试覆盖时间与份数的交集、边界日期、唯一 ID 去重、容器及旧版本保护、无标签归属、跨项目引用、默认预览，以及删除前状态变化时中止。测试通过模拟 Docker API 数据执行，不连接或删除真实 VPS 镜像。
